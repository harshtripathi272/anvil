# Taste
- Context vault lives at `D:/Obsidian/Obsidian Vault/vault` (Obsidian vault + git repo). The path contains a space — always quote it in shell commands. It is authoritative project context shared across Claude Code, Codex, Hermes, and chat sessions — treat it as shared memory, not scratch space. Confidence: 0.95
- Project folders live under `Projects/` (capital P). Derive the project slug from the git remote name (lowercased, hyphenated); if no git repo, use the working directory name; if neither maps to an existing folder under `Projects/`, ask the user which project this is before creating one — never guess and never create duplicate folders for the same project (e.g. `ocr` vs `hindi-ocr-pipeline`). Confidence: 0.95
- Session start: read `Projects/<project>/overview.md` and `decisions.md`; read only the files under `features/` relevant to the request; do NOT read the whole `sessions/` folder — at most the 2 most recent session files, and only if the user references past work or the task continues something unfinished. Confidence: 0.95
- If the project folder doesn't exist, create it with `overview.md`, `decisions.md`, `todo.md`, and empty `features/` and `sessions/` directories. Confidence: 0.95
- Write to the vault proactively (don't wait to be told the session is ending) when ANY of: a non-obvious technical decision is made (a choice between real alternatives); code that changes project architecture or interfaces is written; something is discovered that would cost time to rediscover (bug cause, API quirk, dead end that didn't work); or the user explicitly says to log it. Confidence: 0.95
- Do NOT write vault entries for: single-file edits, formatting, answering a question, failed attempts the user immediately abandoned, or anything re-derivable in two minutes. "A vault full of trivial entries is worse than no vault." Confidence: 0.95
- Vault file conventions: `overview.md` = current truth (goal, stack, status), rewritten in place, kept under 50 lines (excess belongs in `features/`); `decisions.md` = append-only, each entry has date, the decision, alternatives rejected, and the reason — never edit or delete past entries, append a reversal that references the original; `features/<topic>.md` = one file per feature/sub-topic, split when past ~200 lines; `sessions/YYYY-MM-DD_claude-code.md` = what happened this session; `todo.md` = open work items. Confidence: 0.95
- Session file format: frontmatter with `tool: claude-code`, `project: <project-slug>`, `date: YYYY-MM-DD`, `tags: [<topics>]`, then sections `## What was done`, `## Decisions made`, `## Open questions / next steps`. Cross-link related notes with `[[wikilinks]]` (e.g. link a session file to the feature files it touched). Confidence: 0.95
- Before writing anything to the vault, read the target file first and extend it — never overwrite a file that hasn't been read. If the update contradicts what's already there, say so in the reply rather than silently replacing it. Confidence: 0.95
- Hard rules: never write secrets, API keys, `.env` contents, or credentials into the vault; the vault holds context and reasoning, not code — don't copy source files into it, reference paths instead; never `git push` the vault (Obsidian Git handles sync) though `git add`/`commit` inside the vault is fine if asked; whenever writing to the vault, report which files were written in one line. Confidence: 0.95
